# Android Build Worker

This worker turns the Android project generated by the Web to Android App Builder into a
real, signed, verified release APK (and optionally an .aab). It runs Gradle, so it needs a
Linux host with the Android SDK and a JDK - the Docker image below installs both.

## What it does

1. Receives a build request with a signed URL for the generated Android source package.
2. Downloads and unpacks the project into a unique build directory.
3. Generates the Gradle wrapper, then runs gradle assembleRelease.
4. Signs the APK (zipalign + apksigner) with a release keystore it creates and keeps locally.
5. Verifies the APK: file exists, contains AndroidManifest.xml and classes.dex, the signature
   verifies, and the declared package name, version code and version name match the request.
6. Stores the artifacts and serves them with the correct Android MIME type.

Only after every verification step passes does the build report APK READY.

## Requirements

- A Linux host or VM with Docker, at least 4 GB RAM and around 12 GB of free disk.
- Outbound internet access from the container: Gradle downloads the Android Gradle Plugin,
  Kotlin and AndroidX dependencies on the first build.
- A public HTTPS address for the worker (reverse proxy, tunnel or load balancer) so the
  browser can download finished artifacts. Builds and uploads are protected by
  WORKER_AUTH_TOKEN; download links carry their own per-build tokens.

## Deploy

Copy the folder to your server, then:

    cp .env.example .env
    # edit .env: set WORKER_AUTH_TOKEN to a long random secret, set WORKER_PUBLIC_URL
    docker compose build
    docker compose up -d

The image build downloads the Android command line tools, platform android-34 and build-tools
34.0.0, plus Gradle 8.9. It takes a few minutes the first time.

Check it:

    curl http://localhost:8080/health

## Configure the app

In the builder app, open Settings, paste the worker URL and the same token, then press
Test connection. The dashboard switches from BUILD WORKER OFFLINE to a live status panel.

## HTTP API

    GET  /health                        no auth, returns SDK/JDK/Gradle/disk/queue status
    POST /build                         auth, body: buildId, appName, packageName, websiteUrl,
                                        versionName, versionCode, buildType, sourceZipUrl
    GET  /build/{buildId}/status        auth, returns status, stage, progress, artifacts
    POST /build/{buildId}/cancel        auth, cancels a running build
    GET  /build/{buildId}/apk           token, returns the signed APK
    GET  /build/{buildId}/aab           token, returns the signed app bundle
    GET  /build/{buildId}/source        token, returns the full source archive

Authenticated calls send the header:

    Authorization: Bearer <WORKER_AUTH_TOKEN>

## Security notes

- Every build runs in its own directory, and the build configuration is validated (package
  name, version code, build type) before any command runs.
- Commands are executed with argument arrays only, never through a shell, so configuration
  values cannot inject shell commands.
- The release keystore and its password are generated on the worker, stored under
  /var/lib/androidbuildworker/keys with owner-only permissions, and are never returned to
  the app or included in the source archive.
- Artifacts are only served with a valid per-build download token.
- Temporary files are removed after BUILD_RETENTION_HOURS (default 72) by a background sweep.

## Scaling

MAX_CONCURRENT_BUILDS controls parallelism; each build can use 2 GB of RAM. Increase it only
with enough memory and disk. For more throughput, run several workers behind one address.
